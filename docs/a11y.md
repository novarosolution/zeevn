# Accessibility (a11y)

Zeevan customer web and React Native surfaces are audited against WCAG 2.1 AA on critical paths. Automated checks run in CI; manual screen-reader scripts cover auth and checkout.

## Tooling

| Tool | Purpose |
|------|---------|
| [@axe-core/playwright](https://github.com/dequelabs/axe-core-npm/tree/develop/packages/playwright) | E2E scans; **fails on `critical` and `serious`** violations |
| [eslint-plugin-react-native-a11y](https://github.com/FormidableLabs/eslint-plugin-react-native-a11y) | Static RN a11y rules on `src/**/*` |
| `node scripts/axe-report.js` | JSON summary for docs / regression (`tests/e2e/reports/axe-summary.json`) |

```bash
npm run export:web
npx serve -s dist -l 8081 &
E2E_BASE_URL=http://127.0.0.1:8081 npm run test:a11y
npm run test:a11y:report   # writes axe-summary.json
```

ESLint: `npm run lint` (includes `react-native-a11y` basic rules).

## Focus and keyboard

- **Skip to main**: first tab on web focuses “Skip to main content” (`WebAppHeader`); targets `#main-content`.
- **Header**: Shop tabs are `tab` / `tablist`; search opens overlay; ⌘/Ctrl+K focuses search.
- **Overlays**: cart drawer, search overlay, and modals use focus trap helpers (`webStacking` z-index ladder).
- **Auth**: Enter submits; links reachable by Tab; password visibility toggle is a labeled button.

## Color and motion

- Body text targets **4.5:1** on parchment (`#FAFBFD`); large type (≥18px or 14px bold) **3:1**.
- Prefer `semanticPalette.ink` / `textSecondary` over `textMuted` or brass for small copy.
- Animations (GSAP, Reanimated, CSS transitions) should respect `useReducedMotion()` / `prefers-reduced-motion` (see `ThemeContext`, `PageTransition`, skeleton shimmer).

## Screen reader test scripts

Run on **web** (Safari + VoiceOver) or **native** builds. Complete auth + checkout on at least one mobile platform.

### VoiceOver — macOS Safari (auth)

1. Open `/login`. Rotor → **Headings**: expect one level-1 (“Sign in” or equivalent).
2. Tab to **Skip to main** → activate; focus should land in the form region.
3. Swipe through **Email** and **Password** fields; each should announce label + “text field” + value.
4. Activate **Show password**; state should toggle (“selected” / “not selected”).
5. Activate **Sign in**; on error, listen for inline error text (no reliance on color alone).
6. Follow **Forgot password?** and **Create account** links; each should announce as a link with a clear name.
7. On `/register`, confirm **Terms** checkbox announces role and checked state.

### VoiceOver — iOS (auth)

1. Settings → Accessibility → VoiceOver → on. Open app → Login.
2. Two-finger swipe down (read all) from top: brand, then form title, then fields.
3. Double-tap primary button; verify error or success is spoken.
4. Repeat register flow including password strength if shown.

### TalkBack — Android (auth)

1. Settings → Accessibility → TalkBack → on.
2. Explore by touch: each field should read label before value.
3. Submit invalid form; confirm error message is focused or read after submit.

### Checkout / cart (web + native)

1. Add item → open cart (drawer or `/cart`).
2. Confirm cart **badge** update is announced (live region / “N items” on cart control).
3. Step through quantity controls; each button should have a clear name (“Increase quantity”, etc.).
4. Apply coupon (if shown): error/success should be announced.
5. Proceed to checkout controls; verify **Place order** / payment CTA is reachable and labeled.
6. Empty cart: empty state should be announced as a single landmark region with action button.

## Known gaps / follow-ups

- PDP axe test requires E2E API + seed product (`ensureE2EProductId`).
- Account sub-routes (`/account/*`) not in default axe route list; extend `tests/e2e/a11y.spec.ts` as needed.
- Some admin/ops screens are out of scope for customer critical paths.
- ESLint `react-native-a11y` warnings are incremental; treat `no-nested-touchables` as blocking.
